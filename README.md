## Что это за проект

Изначальная задача была практической: превратить большой товарный прайс в понятный электронный каталог для оптовых клиентов.

По мере работы каталог вырос в полноценный web-инструмент с поиском, категориями, вариантами товаров, избранным, корзиной и подготовкой обращения менеджеру. Приоритетом была не максимальная функциональность сама по себе, а **точность товарных данных и устойчивый пользовательский путь от поиска до заявки**.

Это не демонстрационный набор экранов: интерфейс работает на реальной товарной структуре, где критично не смешать цену, цвет, размер, фотографию и идентификатор разных вариантов одной модели.

## Архитектура решения

```text
Excel / товарный прайс
        ↓
очистка + нормализация + проверка данных
        ↓
покупательская группировка моделей и вариантов
        ↓
data/catalog-index.json ───────→ основной каталог
        │
        └── data/details/* ─────→ характеристики и галереи по требованию
                                      ↓
                             HTML / CSS / JavaScript
                                      ↓
                 поиск · категории · карточка · избранное · корзина
                                      ↓
                   GitHub Pages + Cloudflare Web Analytics
```

Проект работает без frontend-фреймворка и отдельного сборщика. Это позволило сохранить простую публикацию, прозрачную структуру и контроль над загрузкой данных.

## Ключевые технические решения

### 1. Точная идентификация товара

Карточки опираются на реальные `sourceId`. Похожие названия сами по себе не считаются основанием для объединения товаров.

Это снижает риск появления несуществующих сочетаний цены, цвета, размера или фотографии. Текущий публикационный каталог сохраняет все **1 196 покупаемых вариантов**, а `sourceId` остаются уникальными.

### 2. Подготовка данных отдельно от интерфейса

Покупательская группировка формируется из проверенных данных заранее. Одна конструктивная модель отображается как одна карточка, а подтверждённые исполнения остаются вариантами внутри неё.

У каждого варианта сохраняются собственные:

- цена;
- характеристики;
- фотографии;
- идентификатор корзины.

### 3. Разделение данных для более быстрой загрузки

Главный каталог использует компактный `data/catalog-index.json`. Полные характеристики и галереи разделены на небольшие блоки в `data/details/` и загружаются только при открытии конкретной карточки.

### 4. Сохранение контекста пользователя

Категория, поисковый запрос, сортировка, номер страницы и позиция прокрутки сохраняются в истории браузера.

При возврате назад пользователь попадает в прежнее место каталога, а не начинает поиск заново.

### 5. Устойчивость к отдельным сбоям загрузки

Для detail-данных предусмотрен резервный запрос к `raw.githubusercontent.com` той же ветки `main`, чтобы единичная ошибка загрузки не останавливала весь каталог.

### 6. Аналитика без собственных просмотров

Cloudflare Web Analytics подключается для обычных посетителей. Для браузеров команды предусмотрен внутренний режим, при котором аналитический маяк не загружается.

Моя задача состояла не в том, чтобы принять сгенерированный результат как готовый, а в том, чтобы:

- формулировать требования;
- разбивать работу на проверяемые этапы;
- сопоставлять решения с реальными товарными данными;
- находить несоответствия;
- уточнять правила;
- повторно проверять результат после изменений.

Продуктовая логика, критерии качества и финальная проверка оставались отдельной частью работы.
